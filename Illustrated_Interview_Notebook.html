Next Greater Element — watch the stack work

Given nums = [4, 2, 6, 3, 7], find the first strictly greater value to the right of each element.

Memory hook: “The new giant answers the smaller numbers waiting on the stack.”

Same tool, opposite direction

Next Greater ElementDecreasing ↓Greater

Use a stack of indices, not just values. That way we can write each answer into the correct position. Try the buttons to follow the algorithm one number at a time.

Start: nothing processed yet. Press Next step.

Step 0 of 5
Stack (indices): [] · Answers: [?, ?, ?, ?, ?]

Full Python solution

def next_greater(nums):
    answer = [-1] * len(nums)
    stack = []  # indices awaiting a greater value

    for i, value in enumerate(nums):
        while stack and nums[stack[-1]] < value:
            previous = stack.pop()
            answer[previous] = value
        stack.append(i)

    return answer

# [6, 6, 7, 7, -1]
Invariant

Indices in the stack refer to values in non-increasing order, bottom to top. None has found its next strictly greater value yet.

Complexity

O(n) time: each index is pushed once and popped at most once. O(n) auxiliary space for stack and answer.

Check yourself: why not pop on equal values?

Because the question asks for a strictly greater element. For [3, 3, 5], both 3s must wait for 5.

Interview explanation — say it out loud

“I scan left to right and keep indices whose next greater value is unknown. The stack is monotonic decreasing by value. When a larger value arrives, it resolves every smaller value on top of the stack. Each index enters and leaves the stack at most once, so the algorithm is linear.”

LESSON 01 · TWO POINTERS · EASY

Best Time to Buy & Sell Stock

The left pointer is the cheapest day seen so far. The right pointer is today. We are not maintaining a conventional shrinking window: we maintain the best buying opportunity.

How to derive the solution

  1. Initialize min_price to infinity and best to zero.
  2. For each price, compute profit if selling today using the cheapest earlier price.
  3. Update best profit; then update the minimum price.
  4. Never sell before buying.

Reference implementation

def max_profit(prices):
    cheapest = float('inf')
    best = 0
    for price in prices:
        best = max(best, price - cheapest)
        cheapest = min(cheapest, price)
    return best
Worked example

[7, 1, 5, 3, 6, 4] → cheapest becomes 1; selling at 6 yields 5.

Common traps

Do not move left forward just because a price drops slightly; update it only when a new minimum appears. An empty or decreasing sequence returns 0.

Interactive trace

Say this in the interview

I scan prices once while maintaining the cheapest prior purchase. Every day is a candidate sale; I update the best achievable profit. Time O(n), space O(1).
🧠 Recall check

For [8, 4, 7, 2, 5], what is the maximum profit?

3 — buy at 4 and sell at 7, or buy at 2 and sell at 5.
LESSON 02 · SLIDING WINDOW · MEDIUM

Longest Substring Without Repeats

A window [left, right] must contain unique characters. Expand right; when the new character repeats, move left until uniqueness is restored.

How to derive the solution

  1. Keep a set of characters currently in the window.
  2. Before adding s[right], remove characters from the left while the new character is already present.
  3. Add the character and record right − left + 1.
  4. Each character enters and leaves at most once.

Reference implementation

def length_of_longest_substring(s):
    seen = set()
    left = best = 0
    for right, char in enumerate(s):
        while char in seen:
            seen.remove(s[left])
            left += 1
        seen.add(char)
        best = max(best, right - left + 1)
    return best
Worked example

"abba": after the second b arrives, remove a then the first b; valid window is "b". Later window "ba" has length 2.

Common traps

The repair is a while loop, not a single if. Do not count a window until it is valid.

Interactive trace

Say this in the interview

My invariant is that the active window contains no duplicates. I expand right, repair violations from the left, and track the maximum valid length. O(n) time, O(min(n, alphabet)) space.
🧠 Recall check

In "abba", when the second b arrives, how many characters must be removed?

Two: first a, then the earlier b.
LESSON 03 · SLIDING WINDOW · HARD

Minimum Window Substring

The direction flips: expand until the window is valid; then shrink while it remains valid, recording the shortest valid answer.

How to derive the solution

  1. Count required character multiplicities in t.
  2. Track window counts and how many distinct requirements are satisfied.
  3. Expand right until all requirements are satisfied.
  4. While valid, record the best substring and remove s[left], stopping when invalid.

Reference implementation

from collections import Counter

def min_window(s, t):
    if not t or not s:
        return ''
    need = Counter(t)
    have = {}
    formed = left = 0
    best_len, best_start = float('inf'), 0
    for right, char in enumerate(s):
        have[char] = have.get(char, 0) + 1
        if char in need and have[char] == need[char]:
            formed += 1
        while formed == len(need):
            if right - left + 1 < best_len:
                best_len, best_start = right - left + 1, left
            old = s[left]
            have[old] -= 1
            if old in need and have[old] < need[old]:
                formed -= 1
            left += 1
    return '' if best_len == float('inf') else s[best_start:best_start + best_len]
Worked example

s="ADOBECODEBANC", t="ABC" → "BANC". Duplicates matter: t="AABC" needs two A characters.

Common traps

A set cannot represent duplicate requirements. The answer is updated while valid, before removing the left character.

Interactive trace

Say this in the interview

I maintain required frequencies and a count of satisfied distinct requirements. After expansion makes the window valid, I shrink greedily while recording the minimum. O(|s|+|t|) expected time.
🧠 Recall check

Why shrink while valid, rather than while invalid?

Because we seek the smallest window that still satisfies all required counts.
LESSON 04 · PREFIX SUM · MEDIUM

Subarray Sum Equals K

If prefix[j] − prefix[i] = k, then the subarray between them sums to k. For the current running sum P, count earlier prefixes equal to P − k.

How to derive the solution

  1. Seed frequencies with {0:1} for subarrays starting at index 0.
  2. Add the current number to the running sum.
  3. Add count[prefix − k] to the answer.
  4. Then increment count[prefix].

Reference implementation

def subarray_sum(nums, k):
    counts = {0: 1}
    running = answer = 0
    for num in nums:
        running += num
        answer += counts.get(running - k, 0)
        counts[running] = counts.get(running, 0) + 1
    return answer
Worked example

nums=[1, 2, 1, 2], k=3 → three subarrays: [1,2], [2,1], [1,2].

Common traps

We seek an earlier prefix of running − k, not k − running. Sliding window is unreliable with negative numbers.

Say this in the interview

A subarray sums to k exactly when two prefix sums differ by k. I count prior prefix sums in a hash map. O(n) time and O(n) space.
🧠 Recall check

Why initialize counts[0] = 1?

To count subarrays beginning at the first element.
LESSON 05 · HASH SET · MEDIUM

Longest Consecutive Sequence

Only start walking from a sequence beginning. A number x is a start exactly when x−1 is absent.

How to derive the solution

  1. Put values in a set to deduplicate and enable expected O(1) lookup.
  2. For each x, skip it if x−1 exists.
  3. Otherwise walk x, x+1, … while values exist.
  4. Update the longest length.

Reference implementation

def longest_consecutive(nums):
    values = set(nums)
    best = 0
    for x in values:
        if x - 1 in values:
            continue
        y = x
        while y in values:
            y += 1
        best = max(best, y - x)
    return best
Worked example

[100, 4, 200, 1, 3, 2] → walk once from 1 through 4; result 4.

Common traps

If you expand from every number, you repeatedly traverse the same run and can become quadratic.

Say this in the interview

Only sequence starts trigger expansion. Every value belongs to at most one such walk, giving expected O(n) time and O(n) space.
🧠 Recall check

Is 3 a valid starting point in {1,2,3,4}?

No. Its predecessor 2 is present.
LESSON 06 · STACK · MEDIUM

Evaluate Reverse Polish Notation

When an operator arrives, pop the right operand first, then the left operand. The expression is left OP right.

How to derive the solution

  1. Push numbers onto a stack.
  2. On an operator, pop right then left.
  3. Evaluate and push the result.
  4. Return the final stack element.

Reference implementation

def eval_rpn(tokens):
    stack = []
    for token in tokens:
        if token not in {'+', '-', '*', '/'}:
            stack.append(int(token))
            continue
        right = stack.pop()
        left = stack.pop()
        if token == '+': result = left + right
        elif token == '-': result = left - right
        elif token == '*': result = left * right
        else: result = int(left / right)  # truncate toward zero
        stack.append(result)
    return stack[-1]
Worked example

["10", "6", "2", "-", "/"] → 6−2=4, then int(10/4)=2.

Common traps

Python // floors negative division; the problem generally requires truncation toward zero.

Say this in the interview

The stack holds completed operand values. An operator combines the most recent two, preserving order by popping right before left. O(n) time, O(n) space.
🧠 Recall check

For ["8","3","-"], what are left and right?

left=8, right=3, so the answer is 5.
LESSON 07 · MONOTONIC STACK · MEDIUM

Daily Temperatures

Keep unresolved indices in a decreasing-temperature stack. A warmer incoming day resolves earlier colder days.

How to derive the solution

  1. Walk each temperature with index i.
  2. While stack is nonempty and today is warmer than its top, pop j.
  3. Set answer[j] = i−j.
  4. Push i; unresolved days stay zero.

Reference implementation

def daily_temperatures(temperatures):
    answer = [0] * len(temperatures)
    stack = []  # unresolved indices
    for i, temp in enumerate(temperatures):
        while stack and temperatures[stack[-1]] < temp:
            j = stack.pop()
            answer[j] = i - j
        stack.append(i)
    return answer
Worked example

[73,74,75,71,69,72,76,73] → [1,1,4,2,1,1,0,0].

Common traps

Store indices, not only temperatures, because the answer is the number of days. Equal temperatures do not resolve each other.

Say this in the interview

The stack stores indices of days waiting for a strictly warmer temperature. Each index is pushed and popped once, so time O(n), space O(n).
🧠 Recall check

What kind of stack do we maintain?

A monotonically non-increasing stack of unresolved temperatures.
LESSON 08 · MONOTONIC STACK · HARD

Largest Rectangle in Histogram

An increasing stack of bar indices remembers where heights began. When a shorter bar arrives, popped heights can extend no farther right.

How to derive the solution

  1. Append a conceptual zero-height sentinel at index n to flush all remaining bars.
  2. While current height is lower than the stack top height, pop the index; that popped bar defines the rectangle height.
  3. After popping, the new stack top is the nearest strictly lower-or-equal boundary on the left (or −1 if empty).
  4. Width = current_index − left_boundary − 1. Update area, then push current index.

Reference implementation

def largest_rectangle(heights):
    stack = []
    best = 0
    for i in range(len(heights) + 1):
        current = heights[i] if i < len(heights) else 0
        while stack and heights[stack[-1]] > current:
            height = heights[stack.pop()]
            left = stack[-1] if stack else -1
            width = i - left - 1
            best = max(best, height * width)
        stack.append(i)
    return best
Worked example

[2,1,5,6,2,3] → area 10 (height 5 across bars 5 and 6). When 2 arrives at i=4, pop 6 (width 1), then 5 (width 2).

Common traps

The height is the POPPED bar. The right boundary is i−1, not i. The left boundary is the new stack top after popping; if empty, use −1. The sentinel 0 flushes the stack.

Interactive trace

Say this in the interview

The increasing stack gives me the nearest limiting bars. A shorter incoming bar closes rectangles for taller bars. Each bar is pushed and popped once, giving O(n) time and O(n) space.
🧠 Recall check

When popping height 5 at i=4 in [2,1,5,6,2,3], what is width?

2. After popping, the left boundary is index 1, so width = 4−1−1 = 2.
LESSON 09 · TWO HEAPS · HARD

Median From Data Stream

Maintain a max-heap for the lower half and min-heap for the upper half. The lower heap can have at most one extra element.

How to derive the solution

  1. Push into the lower half (negate values because heapq is a min-heap).
  2. Move the largest lower value to upper to restore ordering.
  3. If upper becomes larger, move its minimum back to lower.
  4. For odd count, median is lower max; for even, average both tops.

Reference implementation

import heapq

class MedianFinder:
    def __init__(self):
        self.low = []   # negatives: max-heap
        self.high = []  # min-heap

    def addNum(self, num):
        heapq.heappush(self.low, -num)
        heapq.heappush(self.high, -heapq.heappop(self.low))
        if len(self.high) > len(self.low):
            heapq.heappush(self.low, -heapq.heappop(self.high))

    def findMedian(self):
        if len(self.low) > len(self.high):
            return -self.low[0]
        return (-self.low[0] + self.high[0]) / 2
Worked example

Insert 1, 5, 2 → lower=[2,1], upper=[5], median=2.

Common traps

heapq is a min-heap by default. Negate values for max-heap behavior. Distinguish heappushpop (push then pop smallest) from heapreplace (pop then push, requires nonempty heap).

Say this in the interview

Two heaps partition the stream around the median. Insertion costs O(log n); querying the median costs O(1); storage O(n).
🧠 Recall check

What is the median of [1, 2, 5, 8]?

(2+5)/2 = 3.5.
LESSON 10 · AI ENGINEERING · CORE

Agent Loops & Tool Calling

The model proposes a tool call; application code validates and executes it. The loop is bounded and maintains explicit state.

How to derive the solution

  1. Define tool schemas and authorization checks.
  2. Model selects an action; validate tool name, arguments, and permissions.
  3. Execute tool in application code and append structured result to state.
  4. Stop on completion, deadline, budget, no-new-information, or maximum turns.

Reference implementation

async def run_agent(model, tools, messages, deadline, max_turns=8):
    for turn in range(max_turns):
        if remaining(deadline) <= FINALIZATION_RESERVE:
            return finalize_partial(messages, reason='deadline')
        response = await model.next(messages, timeout=remaining(deadline))
        if response.final_answer is not None:
            return response.final_answer
        call = validate_authorize(response.tool_call, tools)
        result = await execute_with_deadline(call, deadline)
        messages.append({'tool': call.name, 'result': result})
    return finalize_partial(messages, reason='turn_limit')
Worked example

An incident-summary agent reads tickets, retrieves source details, drafts a summary, evaluates evidence coverage, then publishes only after approval or deterministic checks.

Common traps

The snippet is architecture pseudocode: helper functions are intentionally abstract. Do not let an LLM authorize its own actions. Parallel tool calls need explicit dependency rules.

Say this in the interview

I separate probabilistic planning from deterministic enforcement. Code controls permissions, ordering, retries, budgets, and termination. Every tool result becomes explicit state for the next turn.
🧠 Recall check

Who enforces the tool permissions and maximum loop count?

Application code, not the LLM.
LESSON 11 · DISTRIBUTED SYSTEMS · CORE

Idempotency, Timeouts & Unknown Outcomes

A timeout means the client did not receive a definitive answer—not that the server failed to execute. Exactly-once effects require coordination with the side-effect owner.

How to derive the solution

  1. Assign a stable operation ID / idempotency key before the first attempt.
  2. Persist intent and state before invoking the external side effect.
  3. On retry, use the SAME key if the downstream system supports deduplication.
  4. If the outcome is ambiguous and cannot be verified safely, move to UNKNOWN and reconcile; never blindly resubmit.

Reference implementation

# Conceptual durable state machine
# NEW -> SUBMITTING -> CONFIRMED
#                 |-> UNKNOWN -> RECONCILING -> CONFIRMED / FAILED

async def submit_once(op):
    claim = await store.claim(op.id, expected={'NEW', 'RETRYABLE'})
    if not claim:
        return await store.read(op.id)
    try:
        result = await broker.submit(op.payload, idempotency_key=op.id)
    except TimeoutError:
        await store.mark_unknown(op.id)
        return 'UNKNOWN'
    await store.record_confirmed(op.id, result)
    return 'CONFIRMED'
Worked example

Order submission times out after reaching the broker. A second request could duplicate the order. Querying “not found” immediately may still be inconclusive if the original request is in flight.

Common traps

A local database key does not magically deduplicate at an external broker. Lease ownership is not the same as downstream idempotency. The example is pseudocode and depends on the broker’s actual API semantics.

Say this in the interview

I treat timeouts as ambiguous outcomes. I persist the operation ID, use downstream idempotency where guaranteed, and reconcile unknown states before any new submission. This protects external side effects from duplication.
🧠 Recall check

Why can “not found” be insufficient after a timeout?

The original request may still be executing or not yet visible in the query index.
LESSON 12 · DISTRIBUTED SYSTEMS · ADVANCED

Leases, Fencing Tokens & Recovery

A lease prevents competing active workers only while ownership is valid. A paused worker may wake after expiry; fencing tokens prevent stale owners from writing.

How to derive the solution

  1. Acquire lease with an atomic conditional write and monotonically increasing token.
  2. Worker includes token on protected writes.
  3. Resource rejects writes with tokens older than the greatest accepted token.
  4. Renew lease while active; if renewal fails, stop and let a new worker recover from durable state.

Reference implementation

# Conceptual DynamoDB conditional acquisition:
# UPDATE lease SET owner=:me, expires=:new_expiry,
#   generation = generation + 1
# WHERE expires < :now OR owner=:me
# Return new generation as fencing token.

# Protected downstream operation must reject stale generations:
# if incoming_generation < last_accepted_generation: REJECT
Worked example

Worker A holds token 17, pauses, and expires. Worker B obtains 18. A wakes; the protected resource must reject A’s token 17.

Common traps

A lease by itself is not a correctness guarantee. Clock skew and token enforcement matter; the resource must actually validate the fencing token.

Say this in the interview

I combine an atomic lease with a monotonically increasing fencing token. The token is checked by the protected resource, so a stale lease holder cannot corrupt state after resuming.
🧠 Recall check

Can a lease alone prevent a paused old worker from writing after expiry?

No. It needs downstream fencing or an equivalent conditional/version check.
LESSON 13 · AI ENGINEERING · CORE

Production RAG: Retrieve, Rerank, Ground

RAG separates evidence retrieval from answer generation. A correct answer requires finding the right source AND faithfully using it.

How to derive the solution

  1. Ingest documents, normalize and chunk at meaningful boundaries; attach metadata and ACLs.
  2. Embed and index chunks; at query time use keyword/vector/hybrid retrieval.
  3. Rerank candidates; filter by access rights and evidence quality.
  4. Generate an answer with citations, abstaining or qualifying unsupported claims; evaluate retrieval and answer separately.

Reference implementation

def answer_with_rag(question, principal):
    candidates = hybrid_search(question, top_k=30)
    authorized = [c for c in candidates if can_read(principal, c)]
    evidence = rerank(question, authorized)[:6]
    if not evidence:
        return {'answer': 'Insufficient evidence', 'citations': []}
    draft = generate_grounded(question, evidence)
    return verify_citations_and_claims(draft, evidence)
Worked example

If a generated answer omits a critical policy exception, ask whether the exception was retrieved. If absent, debug retrieval; if present but ignored, debug generation/prompting.

Common traps

This is design pseudocode. Embedding similarity is not proof of truth. ACL checks must happen before source content reaches the model.

Say this in the interview

I instrument retrieval recall and answer groundedness independently. I preserve source metadata and permissions, rerank before generation, and verify that citations actually support the claims.
🧠 Recall check

A correct source was retrieved but the answer contradicts it. Which stage failed?

Generation/grounding, not initial retrieval.
LESSON 14 · AI ENGINEERING · CORE

LLM Evaluation & Safe Rollout

Measure groundedness (is each claim supported?) separately from completeness (did we cover important source points?). Both can fail independently.

How to derive the solution

  1. Build representative labeled and adversarial evaluation sets.
  2. Track retrieval quality, groundedness, completeness, tool choice, latency, token cost, and failure rate.
  3. Use deterministic checks where possible and an independent evaluator for nuanced judgments; calibrate against human review.
  4. Run shadow mode, compare to baseline, canary gradually, and set rollback thresholds.

Reference implementation

def evaluate(summary, source, required_points):
    grounded = judge_claim_support(summary, source)
    covered = judge_key_point_coverage(summary, required_points)
    return {
        'groundedness': grounded,
        'completeness': covered,
        'accept': grounded >= 0.95 and covered >= 0.90,
    }
# Thresholds are illustrative, not universal.
Worked example

A summary can be fully grounded but miss half the important incidents; it is truthful but incomplete. Another can cover all topics while inventing a resolution; it is complete-looking but ungrounded.

Common traps

Evaluator models can be wrong. Guard against judge bias, dataset leakage, and cost blowups from unbounded retries.

Say this in the interview

I evaluate claim support and key-point coverage independently, then consider operational metrics. Shadow comparisons and human review gate promotion before traffic ramps.
🧠 Recall check

Can an answer be grounded but incomplete?

Yes: all its claims can be supported while it omits key facts.
LESSON 15 · AI INFRA · CORE

Deadlines, Backpressure & Graceful Degradation

Bound work at admission, execution, and finalization. A queue without admission control just hides overload.

How to derive the solution

  1. Apply per-tenant rate limits and global concurrency caps.
  2. Use bounded queues; reject with 429 for client-specific throttling or 503 for service overload as appropriate.
  3. Pass remaining deadline to tools and reserve time for finalization.
  4. On deadline, return partial results with explicit missing evidence rather than fabricating completeness.

Reference implementation

async def handle(req, deadline):
    if not tenant_quota_available(req.tenant):
        return response(429, 'rate limit')
    if not capacity.try_acquire():
        return response(503, 'overloaded')
    try:
        return await run_bounded(req, deadline=deadline,
                                 finalization_reserve_ms=500)
    finally:
        capacity.release()
Worked example

An agent with a 10-minute deadline should stop starting expensive retrieval near the end and use remaining time to assemble a partial, evidence-labeled report.

Common traps

429 vs 503 depends on cause and API contract. Queueing increases waiting time; it does not create capacity.

Say this in the interview

I enforce bounded admission, concurrency, and total deadlines. I propagate time budgets to tools and reserve finalization time, which protects latency and avoids misleading incomplete output.
🧠 Recall check

What happens if the queue is full?

Apply explicit admission policy, such as 429/503, instead of unlimited buffering.
PART II · AI SYSTEM DESIGN

The system-design answer framework

Use this repeatable structure for AI platform, RAG, agent, and inference design interviews. The key is to make requirements and trade-offs explicit rather than listing services.

1. Clarify

Who are users? Read vs write actions? Accuracy, latency, volume, compliance, data sensitivity, and budget?

2. Draw the path

API/admission → durable queue/workflow → tools or retrieval → model → evaluator → persistence → response.

3. Failure boundaries

Retryable vs terminal vs ambiguous. Idempotency keys, leases, deadlines, authorization, audit, and reconciliation.

4. Prove it works

Offline evals, shadow traffic, canaries, p95 latency, quality, cost per successful run, and rollback.

  2. Design a customer-support agent: tool permissions, approval gates, handoff, side-effect safety.
  3. Design an LLM serving platform: routing, batching, autoscaling, tail latency, caching.
  4. Design an LLM evaluation pipeline: datasets, judge calibration, regressions, canaries.
  5. Design a code-review agent: repository access, sandboxing, evidence, PR permissions.
  6. Design distributed inference: parallelism choices, communication costs, fault tolerance.
Sample 90-second answer: production RAG

“I would clarify document sensitivity, freshness, and latency first. Ingestion extracts and chunks documents, preserves version and ACL metadata, and builds hybrid indexes. At query time I authenticate the caller, retrieve candidates, enforce ACLs, rerank, and pass a small evidence set to the model. The answer includes citations, and unsupported claims trigger abstention or a clarification. I separately evaluate retrieval recall, citation support, answer completeness, p95 latency, and cost. I would shadow-test changes before canary rollout, and log document versions so failures are reproducible.”
