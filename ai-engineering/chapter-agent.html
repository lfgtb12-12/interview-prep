What Is an AI Agent?

Build an intuition for what makes a system agentic, then trace a tool call through its real control boundaries.

Imagine you ask: “Find out why a customer’s order was delayed, and draft a reply.” A language model can write a plausible response immediately—but that is not enough. The facts live in the order service, delivery logs and perhaps a support knowledge base. A useful agent must choose which sources to consult, examine their responses, recover when one fails, and decide when it has enough evidence to answer.

Core mental model: The model chooses among permitted next actions; the surrounding application controls execution, permissions, state, budgets and safety. Model proposes; code disposes.

The word agent is overloaded. For interviews, define it operationally: an application where a model dynamically selects actions or next steps based on task state and observations. Autonomy exists on a spectrum; no specific framework or multi-agent architecture is required.

1. Which architecture would you choose?

Single model response

Useful when all necessary facts are provided. Low latency, but no independent source lookup.

Fixed workflow

Program decides lookup order → policy check → draft. Easier to test and control when steps are predictable.

Agentic loop

Model chooses next allowed tool based on findings. More flexible with unpredictable questions, but needs stronger evals and safeguards.

Tradeoff: An agent adds latency, cost, failure modes and prompt-injection surface. Choose it when adaptive routing actually improves task success compared with a simpler baseline.

Interview distinction: Tool calling alone does not prove a system is an agent. A predetermined sequence of LLM tool calls can still be a fixed workflow.

4. How the code maps to the diagram

In production, model responses are structured messages containing either a final response or proposed tool calls. The controller must validate them before execution. This small standalone Python example simulates a model so you can focus on control flow.

def lookup_order(order_id: str) -> dict:
    return {"order_id": order_id, "status": "delayed", "reason": "weather"}

TOOLS = {"lookup_order": lookup_order}

def run(model, max_steps=4):
    observations = []
    for step in range(max_steps):
        proposal = model(observations)
        if proposal["kind"] == "final":
            return proposal["answer"]
        name = proposal["tool"]
        if name not in TOOLS:
            raise ValueError(f"Unapproved tool: {name}")
        args = proposal["args"]
        if name == "lookup_order" and (
            set(args) != {"order_id"} or
            not isinstance(args["order_id"], str)
        ):
            raise ValueError("Invalid tool arguments")
        result = TOOLS[name](**args)
        observations.append({"tool": name, "result": result})
    raise TimeoutError("Step budget exhausted")

def fake_model(observations):
    if not observations:
        return {"kind": "tool", "tool": "lookup_order",
                "args": {"order_id": "A123"}}
    result = observations[-1]["result"]
    return {"kind": "final",
            "answer": f"Order {result['order_id']} is delayed: {result['reason']}."}

assert "weather" in run(fake_model)

Try it: Save as agent_lab.py and run python agent_lab.py. Then write tests for an unauthorized tool, a missing argument, and a model that loops forever. Implement explicit tool-result errors instead of letting every exception escape.

Why is this only an educational scaffold?

Real systems also need authentication and per-tool authorization, durable checkpoints, structured error types, request deadlines, schema validation, token/cost accounting, traces, prompt-injection defenses and versioned tool contracts. For external side effects, implement idempotency or reconciliation rather than blind retries.

5. Failure lab: ambiguous outcomes

Suppose your agent calls send_refund(). The HTTP request times out. Did the refund happen?

A. Retry immediately

Dangerous without server-side idempotency: two refunds may be issued.

B. Assume failure

Wrong: the server may have committed the operation but lost the response.

C. Reconcile first

Use the original idempotency key (if supported) and/or query outcome; otherwise mark UNKNOWN and request review.

A lease or fencing token can stop stale writes to your state store; it does not automatically prevent duplicate effects in an external service.

6. Mid-level + senior-level interviews

Mid-level coding exercise

Build a bounded tool controller. Add typed schemas, unknown-tool rejection, per-call timeouts, deterministic tests and a final-answer fallback. Explain the behavior of each negative test.

Evaluation rubric

Input validation; least-privilege tool routing; maximum steps; correct observation plumbing; deterministic failure handling; test coverage; clear error paths.

Senior-level design scenario

Design an AI support agent processing 50k tickets/day, integrating order lookup and refund issuance. Budget response times, persist jobs, reconcile unknown effects, trace tool calls, audit approvals, and measure task success.

Strong follow-up answers

Separate read-only from side-effecting tools, gate payments with human approval, apply stable operation keys, track PENDING/RUNNING/UNKNOWN/SUCCEEDED, recover with conditional ownership and reconcile before replay. Compare to a fixed workflow using evals and latency/cost/error rates.

Explain it in 60 seconds

“An agent is an application where a model chooses allowed next actions from observations. The model is a planner, not the security boundary. Deterministic code validates and executes each tool call, persists critical state and enforces budgets. I’d favor fixed workflows for predictable processes and introduce model routing only where measured success improves. Side effects need approval, idempotency or reconciliation.”

7. Check your understanding

Without rereading, answer aloud: What makes an agent different from a workflow? Who authorizes tool calls? What changes when tools have side effects? What would your baseline and success metric be?
